# منصة مدار التعليمية

منصة تعليم إلكتروني عربية مبنية بـ Laravel 12 وPHP 8.2+. تدعم حسابات الطلاب والمدرسين والإدارة، الكورسات والدفع عبر Paymob، الاختبارات والشهادات، ورفع الوسائط الخاصة.

## المتطلبات

- PHP 8.2 أو أحدث مع إضافات `gd`, `mbstring`, `fileinfo`, `pdo_mysql` و`pdo_sqlite`.
- Composer 2، وNode.js 22 أو أحدث مع npm.
- MySQL أو MariaDB محليًا. Redis مطلوب فقط عند اختيار Redis للتخزين المؤقت أو الطوابير في الإنتاج.

## التشغيل المحلي

أنشئ قاعدة بيانات MySQL باسم `returnprojects` أو حدّث إعدادات قاعدة البيانات في `.env`، ثم شغّل:

```bash
composer run setup
```

ينشئ الإعداد ملف `.env` عند عدم وجوده، ويثبت الاعتماديات، وينشئ مفتاح التطبيق، ويشغّل الترحيلات، ثم يبني ملفات الواجهة. راجع قيم `.env` المحلية قبل التشغيل. لإنشاء حساب الإدارة، اضبط `ADMIN_NAME` و`ADMIN_EMAIL` و`ADMIN_PASSWORD` في `.env` ثم نفّذ:

```bash
php artisan db:seed
composer run dev
```

يتضمن `composer run dev` خادم Laravel وعامل الطابور وVite. لا تضع بيانات الاعتماد أو مفاتيح الخدمات في ملفات المشروع.

## الاختبارات والفحوصات

```bash
php artisan test
composer run format:check
composer run analyse
npm run build
```

تستخدم الاختبارات SQLite داخل الذاكرة؛ لا تحتاج إلى قاعدة البيانات المحلية. ملف CI يشغّل الفحوصات على PHP 8.2 و8.3 ويبني أصول الواجهة.

## الوظائف والخدمات

- لوحة الطالب والمدرس والإدارة، مع صلاحيات منفصلة وسياسات ملكية للكورسات والدروس.
- مراجعات الكورسات، الكوبونات، الدفع والاسترداد عبر Paymob، اختبارات وشهادات قابلة للتحقق.
- يمكن للمدرّس إضافة مرفقات PDF وصور ومستندات إلى المحاضرة من صفحة تعديلها بعد إنشائها؛ تُحفظ الملفات في التخزين الخاص، ولا ينزّلها إلا المدرّس أو الطالب المشترك في الكورس.
- لكل كورس مجموعة خاصة بالمدرّس والطلاب أصحاب الاشتراكات المدفوعة: إعلانات متعددة الوسائط، روابط خارجية، تعليقات وإعجابات، وتثبيت المنشورات المهمة. تُحدّث المشاركات والتعليقات والتفاعلات دون إعادة تحميل الصفحة. تحفظ مرفقات المجموعة على التخزين الخاص، ولا تُعرض إلا لأعضاء الكورس؛ الحد الأقصى للملف 50 ميجابايت.
- فيديوهات الدروس مخزنة بشكل خاص ولا تُعرض إلا عبر مسار يتحقق من تسجيل الطالب في الكورس. مدة الفيديو يحددها المدرّس، ويحسب الخادم تقدم المشاهدة اعتمادًا على الوقت المنقضي وحدود التقدم بدل الاعتماد على الوقت الذي يرسله المتصفح.

عند الترقية، أدخل مدة فيديو لكل درس قديم من لوحة المدرّس قبل إكماله؛ تُملأ مدة الفيديو الجديد تلقائيًا عند اختياره، ويجب التأكد منها.
- تنبيهات الحساب وتجهيز ملفات الوسائط والتقارير تُعالج عبر الطابور؛ يُرسل رمز تأكيد البريد مباشرةً لتجنب اعتماده على عامل الطوابير.
- مساعد الدعم يعتمد على الأسئلة الشائعة المحلية، ولا يرسل المحادثات إلى مزود ذكاء اصطناعي. يرسل رد الإدارة إلى بريد الزائر اختياريًا بعد حفظه؛ تعذّر البريد لا يلغي الرد، وتظهر للمشرف رسالة توضح ذلك. الإرسال متزامن ليظهر فشل SMTP فورًا ولا يحتاج عامل الطوابير.

## إعدادات الحساب والبريد

ينشئ `php artisan db:seed` حساب إدارة فقط عند ضبط `ADMIN_NAME` و`ADMIN_EMAIL` و`ADMIN_PASSWORD` في البيئة؛ يفشل صراحةً إذا كانت الإعدادات غير صالحة أو البريد يعود لحساب غير إداري. استخدم كلمة مرور قوية وفريدة، ولا تضعها في المصدر.

يتطلب الطلاب تأكيد البريد قبل استخدام المناطق المحمية عبر رمز عشوائي من 6 أرقام صالح لمدة 10 دقائق، مع حد أقصى 5 محاولات لكل رمز. يُحفظ الرمز مشفرًا في قاعدة البيانات، ويُرسل مباشرةً دون الاعتماد على عامل الطوابير؛ عند فشل مزود البريد يبقى الحساب محفوظًا ويمكن إعادة إرسال الرمز. محليًا يكتب `MAIL_MAILER=log` الرمز إلى `storage/logs/laravel.log` بدل إرساله. للإرسال الفعلي، اضبط `MAIL_MAILER` وبيانات SMTP و`MAIL_FROM_ADDRESS` في البيئة الخاصة؛ عند استخدام Gmail استخدم كلمة مرور تطبيق صالحة، لا كلمة مرور الحساب العادية. لا تضع أسرار البريد في المصدر.

## النشر

ابدأ ببيئة staging وتأكد أن الاستضافة توفر PHP 8.2+، وقاعدة MySQL/MariaDB دائمة، وHTTPS، ومساحة تخزين دائمة وقابلة للكتابة، وعامل طوابير دائمًا. جهّز متغيرات البيئة من لوحة الاستضافة، لا من ملفات المصدر:

- `APP_ENV=production`, `APP_DEBUG=false`, عنوان HTTPS في `APP_URL`، ومفتاح `APP_KEY` فريد. تُفعّل ملفات جلسات آمنة عبر HTTPS والمصادقة الثنائية للمديرين والمدرسين افتراضيًا في الإنتاج؛ لا تضبط `SESSION_SECURE_COOKIE=false` أو `REQUIRE_2FA=false` هناك.
- بيانات قاعدة البيانات، إعدادات البريد وPaymob، وقيم الإدارة قبل إنشاء حساب الإدارة.
- النسخ الاحتياطية في الإنتاج تستخدم قرص S3 افتراضيًا؛ اضبط `AWS_BUCKET` وبيانات AWS، أو عيّن `BACKUP_DISKS` إلى قرص خاص ودائم آخر. اضبط `BACKUP_NOTIFICATION_EMAIL` وبريد الإرسال، وضع كلمة مرور قوية وفريدة في `BACKUP_ARCHIVE_PASSWORD` لحماية الأرشيفات.
- اختر `QUEUE_CONNECTION=redis` و`CACHE_STORE=redis` فقط بعد إعداد Redis يمكن الوصول إليه.
- اجعل جذر الويب يشير إلى مجلد `public`، وأعد إنشاء رابط التخزين العام باستخدام `php artisan storage:link`.

لا يفرض التطبيق حدًا إجماليًا لحجم فيديوهات المحاضرات؛ تُرفع الفيديوهات على أجزاء صغيرة إلى مساحة مؤقتة خاصة ثم تُعالج في الطابور. يظل الحجم الفعلي محدودًا بمساحة التخزين وسياسات الاستضافة. يجب أن تسمح إعدادات PHP وApache أو الوكيل العكسي بحجم الجزء الواحد (8 ميجابايت) مع بيانات الطلب؛ فيديوهات الدروس تحفظ على التخزين الخاص ولا يلزم إنشاء روابط عامة لها. ينظف المجدول الرفع غير المكتمل بعد 24 ساعة، لذلك شغّل Laravel Scheduler وعامل الطابور في النشر.

على خادم النشر، ثبّت الاعتماديات وابنِ أصول الواجهة ثم طبّق الترحيلات بعد أخذ نسخة احتياطية من قاعدة موجودة:

```bash
composer install --no-dev --optimize-autoloader --no-interaction
npm ci
npm run build
php artisan migrate --force
php artisan storage:link
php artisan config:cache
php artisan route:cache
```

لا ترفع `.env` أو `vendor` أو `node_modules` أو قاعدة بيانات SQLite المحلية أو سجلات التشغيل أو ملفات البناء القديمة. لا ترفع ملف إعدادات Laravel المخبأ؛ أنشئه على الخادم بعد ضبط البيئة.

شغّل `php artisan schedule:run` كل دقيقة عبر مجدول النظام، وعامل الطوابير أو Horizon كخدمة دائمة تحت مدير عمليات، وتابع الطوابير والمهام الفاشلة. أعد تشغيل العامل بعد كل نشر حتى يحمّل الإصدار الجديد. يتطلب Horizon إضافتي PCNTL وPOSIX؛ على Windows استخدم `php artisan queue:listen` للتطوير. اختبر تسجيل الطلاب والتحقق من البريد ورفع الملفات وPaymob التجريبي والشهادات والاسترداد في staging قبل فتح الموقع.

تُجدول النسخ الاحتياطي اليومي وتنظيفه في `routes/console.php`. اختبر `php artisan backup:run` و`php artisan backup:monitor`، ثم تدرّب على استعادة قاعدة البيانات والملفات في بيئة منفصلة؛ لا تختبر الاستعادة فوق قاعدة الإنتاج. تحقق دوريًا من وصول إشعارات النسخ، ومن إمكان قراءة كلمة مرور الأرشيف عند الاستعادة. كذلك، عند ترقية موقع يحتوي فيديوهات دروس قديمة في التخزين العام، أوقف عامل الطابور وشغّل `php artisan media:secure-lesson-videos` مرة واحدة، وتحقق من وجود الملفات في التخزين الخاص قبل إعادة تشغيل العامل.

روابط ملفات الدروس يجب أن تبقى خاصة؛ لا تعرض أصل تخزينها على CDN عام. تعطيل زر التنزيل والعلامة المائية وسائل ردع فقط ولا تمنع تسجيل الشاشة أو حفظ المحتوى بواسطة مستخدم مخول.

## ملاحظات التطوير

- الطابور والتخزين المؤقت الافتراضيان محليًا يستخدمان قاعدة البيانات. شغّل `php artisan queue:work` إذا لم تستخدم `composer run dev`. تُحفظ فيديوهات الدروس الجديدة مؤقتًا في التخزين الخاص، ثم ينشرها عامل الطابور بالتتابع؛ وفي النشر متعدد الخوادم استخدم مخزن أقفال مشتركًا مثل Redis.
- يمكن استخدام `php artisan horizon` محليًا عند توفر Redis وPCNTL وPOSIX.
- تقرير تسجيل الضغط `tests/Feature/RegistrationLoadTest.php` محاكاة لحدود الطلبات على قاعدة الاختبار، وليس اختبار سعة متزامنًا؛ لا تشغّله على الإنتاج.
- Laravel Debugbar للتطوير المحلي فقط. أصول الواجهة تُبنى عبر Vite، ويمكن إعداد `ASSET_URL` و`PUBLIC_STORAGE_URL` لاستخدام CDN للملفات العامة فقط.
