# تجهيز Madar للرفع على InfinityFree

## قبل البدء

هذا المشروع يستخدم Laravel 12، ويتطلب PHP 8.2 أو أحدث. من لوحة الاستضافة، تأكد أن إصدار PHP والإضافات المطلوبة من Laravel متاحة، خصوصًا `PDO MySQL` و`mbstring` و`OpenSSL` و`fileinfo` و`curl` و`XML` و`ctype`.

الاستضافة المشتركة المجانية قد لا توفر SSH أو Composer أو تشغيل Artisan أو العامل الدائم للطوابير أو Cron. كما قد تقيّد طلبات الاتصال الصادرة وحجم الملفات. لا تعتبر الموقع جاهزًا للإنتاج قبل اختبار تشغيل migrations، ورفع الملفات، وإرسال البريد، والاتصال التجريبي بـPaymob. إذا لم تتوفر هذه المتطلبات، استخدم استضافة Laravel توفر SSH وCron وعامل طوابير وتخزينًا مناسبًا للملفات الخاصة.

## تجهيز الملفات على جهازك

من مجلد المشروع:

1. ثبّت اعتماديات الإنتاج باستخدام ملف القفل:

   ```text
   composer install --no-dev --prefer-dist --optimize-autoloader --no-interaction
   ```

2. ابنِ ملفات الواجهة:

   ```text
   npm ci
   npm run build
   ```

   مجلد `vendor` ومجلد `public/build` مستثنيان من Git، لذلك يجب تضمينهما في الرفع بعد تنفيذ الخطوتين.

3. أنشئ مفتاح التطبيق محليًا لنسخه إلى إعدادات الخادم:

   ```text
   php artisan key:generate --show
   ```

   لا تنشر هذا المفتاح أو تضعه في Git.
4. قبل تجهيز الملفات، نفّذ `php artisan optimize:clear` محليًا، وتأكد من عدم رفع `bootstrap/cache/config.php`؛ ملف الإعدادات المخزّن محليًا قد يحتوي قيمًا غير مناسبة للخادم.

## توزيع الملفات بأمان

1. أنشئ مجلدًا اسمه `madar_app` خارج مجلد الويب `htdocs`، وضع فيه ملفات Laravel، بما فيها `vendor` و`storage` و`bootstrap` و`routes` وملف `.env`. لا تضع هذا المجلد داخل `htdocs`.
2. ارفع **محتويات** مجلد `public` إلى `htdocs`، بما فيها `.htaccess` و`build` وملفات CSS وJavaScript والصور.
3. انسخ `deployment/infinityfree/index.php.example` إلى `htdocs/index.php`. أبقِ اسم مجلد التطبيق `madar_app`، أو عدّل المسار في الملف إذا اخترت اسمًا آخر.
4. لا ترفع `.env` إلى `htdocs`، ولا ترفع قاعدة بيانات التطوير أو ملفات `.git` أو `node_modules`.
5. اجعل `storage` و`bootstrap/cache` قابلين للكتابة بواسطة PHP فقط. لا تجعل ملفات التطبيق أو `.env` متاحة للكتابة العامة.
6. اضبط نسخة الإنتاج من متغيرات البيئة داخل `madar_app/.env` باستخدام [env.production.example](./env.production.example). أدخل بيانات قاعدة البيانات من لوحة الاستضافة، وضع مفتاح التطبيق الذي أنشأته، وعنوان الموقع مع HTTPS. لا ترفع ملف المثال مكان `.env` قبل استكمال القيم.

ابدأ بمجلدات `storage` فارغة (مع إنشاء مجلدات Laravel المطلوبة)؛ لا تنسخ سجلات أو جلسات أو cache أو قاعدة التطوير أو ملفات الطلاب الخاصة من جهازك. إذا كنت تريد نقل صور أو فيديوهات موجودة، انقل الملفات المطلوبة فقط عبر قناة آمنة، وتأكد من المساحة والصلاحيات قبلها.

## قاعدة البيانات والتشغيل

- أنشئ قاعدة MySQL من لوحة الاستضافة. يجب تشغيل migrations الخاصة بالمشروع على قاعدة الإنتاج **مرة واحدة** باستخدام `php artisan migrate --force` من بيئة موثوقة تتصل بقاعدة البيانات. لا ترفع سكربت ويب مؤقتًا لتنفيذ Artisan أو migrations.
- إذا لم توفر الاستضافة طريقة آمنة لتشغيل الأمر، فهذه عائق نشر: لا تفتح الموقع قبل تجهيز المخطط بطريقة موثوقة، والأفضل الانتقال لاستضافة تدعم SSH/CLI.
- تأكد أن ملفات `storage/app/private` تبقى خارج مجلد الويب؛ فهي تحتوي ملفات دروس ومرفقات لا ينبغي إتاحتها كروابط عامة. بعد الرفع، اختبر رفع ملف وفتحه بصلاحيات المستخدم المصرح له فقط.
- `QUEUE_CONNECTION=sync` يتجنب الحاجة إلى عامل دائم، لكنه يشغّل المهام داخل طلب المستخدم وقد يتسبب في بطء أو انتهاء مهلة الطلب. المهام المجدولة الموجودة في المشروع لن تعمل تلقائيًا دون Cron.
- الملفات المرفوعة والصور تعتمد على قابلية الكتابة في `storage`. إذا كانت الاستضافة لا تدعم رابط `public/storage` الرمزي أو تمنع إنشاءه، فقد لا تظهر الملفات العامة المرفوعة؛ اختبر ذلك قبل الإطلاق.
- إعدادات البريد في المثال تستخدم سجل التطبيق فقط، وليست إرسال بريد فعليًا. اضبط SMTP موثوقًا إذا كانت الاستضافة تسمح به.
- اضبط البريد واختبره قبل فتح التسجيل للمستخدمين؛ التحقق من البريد وإعادة تعيين كلمة المرور يعتمدان على وصول الرسائل.
- لا تفعّل بيانات Paymob الحقيقية إلا بعد نجاح اختبار Sandbox للتدفق كاملًا، بما فيه الاتصال الصادر إلى Paymob ووصول callback عبر HTTPS. لا تعِد محاولة الدفع عند الشك في الخصم قبل مراجعة لوحة Paymob.

## فحص ما بعد الرفع

- افتح `/up` وتأكد من استجابة Laravel.
- تحقق من عدم ظهور أخطاء PHP أو تفاصيل داخلية للمستخدم (`APP_DEBUG=false`).
- اختبر الدخول والجلسات، قراءة وكتابة قاعدة البيانات، الصور والملفات الخاصة، والبريد.
- اختبر عملية دفع تجريبية وفشلها وتكرار callback قبل استخدام معاملات حقيقية.
- لا تعتمد على الاستضافة المجانية لتخزين فيديوهات أو ملفات خاصة مهمة دون معرفة حدود التخزين والنسخ الاحتياطي والاسترجاع.
